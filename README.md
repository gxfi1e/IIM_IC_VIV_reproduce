# Reproducibility Guide for the 2D IIM–IBAMR Simulations

## 1. Purpose

This package provides the minimum materials needed to reproduce the 2D immersed interface method (IIM) simulations used for the isolated-cylinder validation case and to understand the workflow used for the present simulations.

Two IBAMR versions are relevant in this work:

- **Validation case:** IBAMR **0.14.0**
- **Present production simulations:** IBAMR **0.16.0**

According to our verification, the update from IBAMR 0.14.0 to 0.16.0 did not alter the IIM framework used here and did not produce any change in the numerical results reported in this study. The compilation procedure described below has been tested with **IBAMR 0.16.0** on both a cluster and a local workstation.

Official IBAMR resources:

- **Downloads:** <https://ibamr.github.io/downloads>
- **Build guide:** <https://ibamr.github.io/building>
- **AutoIBAMR helper project:** <https://github.com/IBAMR/autoibamr>

## 2. Package structure

The package is organized as follows:

.
├── example_IC_compile/                # Source files used to compile the present 2D IIM-IBAMR solver
│   ├── CMakeLists.txt                 # CMake build script
│   ├── example.cpp                    # Main C++ source file (the file extension may be hidden on some systems)
│   └── input2d                        # Example input file used during development and testing
├── IC_mesh/
│   └── cylinder40.e                   # Mesh file for the isolated-cylinder validation case
└── IC_VIV_Ur_5/                       # Validation case at Ur = 5, including input, executable, raw outputs, and post-processing files
    ├── input2d                        # Input file used for this case
    ├── main2d                         # Compiled executable solver
    ├── post.py                        # Post-processing script
    │                                  # Note: Y/D is evaluated as 2*Ymax/D, which is equivalent to (sqrt(2)*Yrms)/D
    │                                  # for purely sinusoidal oscillation
    ├── CD_1.curve                     # Drag-force history
    ├── CDisplacement_1.curve          # Cylinder displacement history
    ├── CL_1.curve                     # Lift-force history
    ├── CTD_1.curve                    # Drag coefficient history
    ├── CTL_1.curve                    # Lift coefficient history
    ├── simulation_log                 # Simulation duration file
    └── computation_results1_101_101_5 # Processed results generated by post.py
### Folder roles

#### `example_IC_compile/`
Compilation folder for the 2D solver.

This folder contains:

- `example` — the customized 2D IBAMR/IIM solver source file
- `CMakeLists.txt` — the CMake build script
- `input2d` — a compile/test input file that may be useful as a reference

#### `IC_mesh/`
Mesh folder.

This folder contains:

- `cylinder40.e` — the Exodus mesh file referenced by the isolated-cylinder case

#### `IC_VIV_Ur_5/`
Validation case folder for the isolated vibrating cylinder at **Ur = 5**.

This folder contains:

- `input2d` — runtime input file
- `main2d` — compiled executable
- `post.py` — optional post-processing script
- output files such as force, displacement, and traction histories (`*.curve`), log files, and summarized results

## 3. Minimum files required

### To compile the solver
At minimum, you need:

- the C++ source file (`example` / `example.cpp`)
- `CMakeLists.txt`
- a working IBAMR installation
- MPI compiler wrappers (`mpicc`, `mpicxx`)
- CMake

### To run a 2D IIM case
At minimum, you need:

- `main2d`
- `input2d`
- all mesh/data files referenced by `input2d`

For the isolated-cylinder validation case in this package, the essential runtime files are:

- `IC_VIV_Ur_5/main2d`
- `IC_VIV_Ur_5/input2d`
- `IC_mesh/cylinder40.e`

## 4. Software requirements

This example uses **CMake**, **MPI**, and **IBAMR**.

### Requirements

- CMake **>= 3.15**
- MPI compiler wrappers: `mpicc`, `mpicxx`
- An installed IBAMR package with `IBAMRConfig.cmake`

### Notes

- On clusters, the exact module names depend on the local environment.
- Replace `cmake/<version>` and `openmpi/<version>` with versions available on your system.
- `IBAMR_DIR` must point to the directory containing `IBAMRConfig.cmake`.

You can locate the IBAMR CMake configuration file using:

```bash
find /usr /usr/local /opt $HOME /ibex -name IBAMRConfig.cmake 2>/dev/null
find /usr /usr/local /opt $HOME /ibex -name ibamr-config.cmake 2>/dev/null
```

For example, if the search returns:

```bash
/home/gongm/autoibamr/packages/IBAMR-0.16.0/lib64/cmake/ibamr/IBAMRConfig.cmake
```

then set:

```bash
-DIBAMR_DIR=/home/gongm/autoibamr/packages/IBAMR-0.16.0/lib64/cmake/ibamr
```

## 5. Building the solver

After IBAMR has been installed following the official build instructions, compile the solver from `example_IC_compile/`.

### Step 1: go to the compilation folder

```bash
cd example_IC_compile
```

### Step 2: load modules if needed

On many clusters this is required:

```bash
module load cmake/<cmake-version>
module load openmpi/<mpi-version>
```

On a local workstation, these commands may not be necessary if CMake and MPI are already available in your environment.

### Step 3: configure and build

```bash
mkdir -p build
cd build

cmake .. \
  -DCMAKE_C_COMPILER=$(which mpicc) \
  -DCMAKE_CXX_COMPILER=$(which mpicxx) \
  -DIBAMR_DIR=/path/to/IBAMR/lib64/cmake/ibamr

cmake --build . -j
```

After a successful build, the executable `main2d` should be generated in the `build/` directory.

---

## 6. Preparing the validation case

### Step 1: copy the executable

Copy the compiled executable from the build folder into the case folder:

```bash
cp example_IC_compile/build/main2d IC_VIV_Ur_5/
```

### Step 2: check the mesh path in `input2d`

The `MESH_FILENAME` entry in `IC_VIV_Ur_5/input2d` must point to the correct mesh file.

A portable choice is a relative path such as:

```text
MESH_FILENAME = "../IC_mesh/cylinder40.e"
```

If an absolute path is used on your machine, update it accordingly before running.

### Step 3: verify the case files

Before launching the case, make sure the following files are present:

- `IC_VIV_Ur_5/main2d`
- `IC_VIV_Ur_5/input2d`
- `IC_mesh/cylinder40.e`

---

## 7. Running the simulation

From the case folder:

```bash
cd IC_VIV_Ur_5
```

### Serial run

```bash
./main2d input2d
```

### Parallel MPI run

```bash
mpirun -np <NPROC> ./main2d input2d
```

where `<NPROC>` is the number of MPI processes.

On HPC systems, the same executable may also be launched through the scheduler environment, for example with `srun`, depending on local practice.

---

## 8. Main outputs

Typical output files produced by the validation case include:

- `CD_1.curve` — drag coefficient history
- `CL_1.curve` — lift coefficient history
- `CDisplacement_1.curve` — displacement history
- `CTD_1.curve`, `CTL_1.curve` — traction-related histories
- `II2d_LMred` — main log/output file
- `simulation_log` — case log
- `computation_results1_101_101_5` — summarized result file

These files are useful for independent checking of the force response, vibration amplitude, and post-processed quantities.

---

## 9. Practical workflow summary

A typical workflow is:

1. Install IBAMR following the official IBAMR build guide.
2. Compile the customized source file in `example_IC_compile/` to generate `main2d`.
3. Copy `main2d` into the desired case folder.
4. Edit `input2d` if needed.
5. Make sure the mesh path in `input2d` is valid.
6. Run the case in serial or parallel.
7. Check the generated `*.curve` files and logs.
8. Run `post.py` if post-processing is needed.

## 11. Reproducibility notes

- If `input2d` contains absolute paths, they must be updated before running on another machine.
- The source file may appear as `example` instead of `example.cpp` if file extensions are hidden by the operating system.
- Not all generated files are required to rerun the case. For rerunning, the essential items are the executable, the input file, and the mesh file.
- For exact agreement with published results, use the original case parameters and the same numerical setup reported in the manuscript.

## 12. Origin of the solver and related reference

The present 2D solver was customized from **IBAMR IIM example 4**:

- <https://github.com/IBAMR/IBAMR/tree/master/examples/IIM/ex4>

For the immersed-interface rigid-body formulation, see:

- E. M. Kolahdouz et al., *A sharp interface Lagrangian–Eulerian method for rigid-body fluid–structure interaction*, **Journal of Computational Physics**, 2021. DOI: <https://doi.org/10.1016/j.jcp.2021.110442>

The isolated-cylinder validation case used here corresponds to:

- M. Gong and B. Dally, *Dynamic response of a cylinder-plate-cylinder system coupling wake-induced and interference effects*, **Physics of Fluids**, 2025, 37(10): 103602. DOI: <https://doi.org/10.1063/5.0289251>
